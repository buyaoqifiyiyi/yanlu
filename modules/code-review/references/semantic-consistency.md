# 跨文件语义一致性

当前变更或故障涉及跨模块表示、默认值或异步状态，或用户明确要求相关审查时使用。范围限于相关生产者、消费者及必要契约；文案和样式小改不触发全仓检查。

## 先确认职责是否相同

- 从需求、调用者和实际输入确认两段实现是否应回答同一个问题。
- 名称或形状相似不能证明应该共享行为；展示格式与机器格式、不同地区规则等可以有意不同。
- 有意不同不报缺陷，不为表面一致性要求抽公共层；意图不明且影响结论时保留疑点。

## 沿值的含义追踪

1. 找到相关值的产生或存储处，确定单位、时区、范围和表示，例如帧/毫秒、分/元、UTC/本地、0–1/百分数。
2. 跟踪它在当前相关链中的转换与读取，包括改名、序列化、派生值和接口边界。
3. 核对下游运算与使用是否仍符合定义；不能因名字看似合理或代码不报错就认定一致。
4. 发现不符时指出两端、具体输入条件和结果差异；已有转换、类型或接口契约应一并考虑。

## 检查默认值和回退顺序

- 对照本次需求与配置读取处，确认显式值、用户配置、环境配置和默认值的实际优先级。
- 按实际语言/解析器区分缺失、空值、0 和 false；不要凭通用经验推定它们等价。
- 不同接口默认值不同，先判断职责与兼容契约，不能只比较数字。

## 检查异步读取依赖

- 找出消费者读取的关键状态由谁创建，检查相关创建与读取之间的顺序和存在性保证。
- 查看实际事务、队列顺序、存在性检查、幂等写入或重试契约，而不是只看事件名称。
- 缺少显式锁不自动构成竞态；查明可达执行顺序、失败表现和已有保证，证据不足只记待核实。
- 保证存在时不报问题；无需为每个安全 handler 建注册表或固定报告项。

## 把发现交回原流程

审查仍保留 Standards / Spec 两轴：编码约定违反进入 Standards，需求行为不符进入 Spec；说明证据和影响，不加第三个强制轴。缺少 spec 时照实保留该限制。

诊断仍先确认原症状并建立适用的复现/反馈路径。本页提供待检假设与查阅点，不代替复现，不把源码推断写成已重现故障。

若已授权修复，覆盖本次相关的生产与消费两端，必要时核查兼容读写及回归；只改一端不能证明差异已消除。只读审查不自动修改实现。

## 完成条件

- 已证实问题、待核实疑点和有意差异可区分；没有问题时允许报告已查范围未发现问题。
- 结论有实际定义、读取、调用或运行证据，不按相似名称、无锁或旧报告直接定罪。
- 检查止于请求及必要关联链，不强制全仓考古、额外代理或发现数量。
