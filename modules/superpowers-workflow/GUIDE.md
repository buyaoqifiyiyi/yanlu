# Superpowers workflow · 本机试用版

将多步骤编码工作和已请求的跨工具任务交接连成可恢复的执行流程。来源及适配范围见 [上游与兼容说明](references/upstream.md)；ECC 交接方法的增量见[包来源](../../references/upstream.md#310-ecc-评估与交接方法增量)。

## 开始与续接

1. 从当前授权、项目指引和已有代码确定交付物、可观察的验收条件及工作范围。方向清楚就执行；只有会改变目标、权限或不可逆后果的缺项才需要用户决定。
2. 使用当前适合的隔离工作区；必要时依宿主能力创建 worktree。已有可用工作区就复用，非 Git 项目使用明确的任务目录。普通读取无需先建立工作区。
3. 优先使用项目已有计划及台账。没有台账时，在项目允许的任务文档目录创建任务专属 `progress.md`；项目没有约定时使用 `work/<task-id>/progress.md`。参考 [台账模板](references/ledger.md)，只保留本任务所需字段。
4. 记录工作区绝对路径、任务/计划身份、验收条件、待办及完成证据。续接时读台账并核对实际文件、Git 历史或测试输出；记录是恢复线索，不是事实的替代。文件与记录不符时说明差异，只重验受影响部分。

开始实现的条件：当前范围、下一项工作和如何验收均已明确。已有完成项核实后继续下一项，保留其内容；没有变化或新疑点时不重复实现或重跑。

## 执行与交接

按可独立验证的交付拆任务，复杂度决定粒度。记录任务之间的接口及文件依赖；共享文件由单一写入者处理。台账在阶段完成、失败、交接或方向变化时更新，写明下一步，避免只存在于聊天中。

单代理默认适用于紧密依赖或小任务；独立工作足够大且当前授权允许时才委派。交接包含：

- 本任务目标与完成条件，必要原始输入及已确认决定；
- 可读资源、独占写入文件/目录、依赖任务及接口；
- 可用工具、已获授权与禁止副作用；
- 应返回的实际修改、运行命令、结果、未解项及下一步。

子代理结果是待核验交接。主代理查看实际差异、核对需求并运行必要检查。工具不支持委派时在当前会话继续，并如实记录独立审查未执行。

跨工具续接仍使用[同一任务台账](references/ledger.md)，补充交接来源、观察时间、接收对象及原始证据位置；保存交接不等于已发送、唤醒接收方或获准继续对外操作。当前执行状态留在任务台账，只有需长期复用的结论或重要交接才按当前已授权的记忆入口保存，并链接回台账和项目权威文档，不另建 ECC 记忆库。检索范围、不完整结果和旧记录失效的处理以该记忆入口规则为准；入口不可访问时说明限制，继续可独立完成的本任务工作。

执行已批准范围直到完成或确实受阻。日常实现选择由代理判断；目标变化、授权缺失或不可逆动作按当前会话规则处理。进度消息简短报告阶段、发现或阻碍。

## 复用现有技能

以当前宿主实际可用技能为准，按其适用条件加载。本包的轻量编码模块约束实现复杂度（原Ponytail能力），只加载相应模块而不启动技能维护实验；[诊断模块](../diagnosing-bugs/GUIDE.md)处理根因诊断；[TDD模块](../tdd/GUIDE.md)在适合或已要求测试先行时使用；[代码审查模块](../code-review/GUIDE.md)处理请求的或复杂改动所需的独立审查。缺失时采用项目已有方法完成相应工作并说明限制。

本技能负责协调，不自动加载上游 `using-superpowers`、强制 TDD 或需求访谈。对已完成代码保持原样，除非当前需求或验证证据要求修改。测试按改动风险选择，既验证目标行为，也覆盖受影响接口；新失败或依赖变化出现时再扩大验证。

## 最终验收

1. 将每项验收条件映射到实际产物和证据；检查范围外修改与未完成项。
2. 保存必要命令的工作目录、退出码、关键输出及对应文件/提交身份；优先保存完整运行日志。没有相关变化的本次有效证据可以复用；历史日志、缓存结果和子代理口头结论不能直接证明当前通过。
3. 区分源码/静态检查、自动测试、真实运行、界面操作、保存重开及导出。只报告实际达到的层级。失败、受阻或未执行的必要验收留在台账与最终回复中。
4. 验收与需求符合度均满足后才将任务标为完成；尚有必要工作时保留下一步和阻碍。交付已授权的产物与简明结论；提交、推送、发布和清理各自遵循当前授权。

台账与证据保留到用户或项目现有清理规则要求处理时。此技能不注册 hook、不升级其他技能、不修改全局指引或外部服务。
