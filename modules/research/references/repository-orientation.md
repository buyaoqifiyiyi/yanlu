# 陌生代码库导览

用于解释项目结构、找到行为归属或说明一条实际代码路径。用户只要理解时只读；同时请求审查、建议或实现时，按该部分的授权和对应模块继续。

## 确定本次入口

1. 先读适用项目指令，再看相关清单、manifest、启动配置与目录；缓存、生成物和无关大文件不默认展开。
2. 从用户问题选一个代表性动作，例如启动命令、HTTP 请求、界面操作或事件；不要求覆盖所有服务。
3. 核实实际入口及当前调用者。README 和文件名提供线索，行为说明须回到当前源码或配置。

已有明确文件位置的单点修复、普通 diff 审查和只要命令的任务，直接走原短路径，不先生成仓库导览。

## 追踪相关执行链

按需要追踪：输入 → 路由/调度 → 核心处理 → 存储或外部作用 → 输出。

- 记录真正接收输入、变换数据、读写状态和返回结果的文件与关键符号。
- 区分公共接口、转发包装与实现职责，确认调用实际落到哪里；同名文件不自动代表行为归属。
- 配置或特性开关影响路径时，说明所读配置下的分支；缺少运行配置时不把候选路径说成已启用。
- 到外部服务、未读模块或动态注册边界时标出已知契约和未确认部分；只补查会影响回答的相邻定义。

需要历史才能解释当前行为时再看相关历史，不为导览重建全仓开发年代。静态阅读无需启动应用、迁移数据或安装依赖。

## 说明证据层级

- **源码定义**：所读文件中能定位的路由、调用和返回行为。
- **运行观察**：实际执行后看到的结果，说明对应条件；未运行不写“已验证运行”。
- **推断**：由已有线索得出的解释，标明依据及仍缺的确认。
- **未覆盖**：会影响用户判断的未读范围或外部条件。

文档与实现不符时指出具体位置，按当前证据解释差异；只读任务不顺手修文档或代码。

## 交付到问题所需深度

用简短结论、关键文件职责和相关执行链回答用户；路径图或表格只在更清楚时使用。先指出从哪里读、哪个文件负责问题中的行为，再展开必要细节。

用户另要问题或改进建议时，区分可确认问题与候选建议，不沿用上游一律禁止建议的规定。没有相关证据时不编质量评价或重构计划。

## 完成条件

- 主要职责与路径能对应到实际读过的代码或配置，解释包含输入与输出。
- 已读范围足够回答本次问题，未冒称理解全仓或实际运行。
- 只读边界和用户原交付范围得到保留，没有附带改动。
