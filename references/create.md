# 创建：来源 → 框架 → 可运行技能

适用于新建人物视角、主题方法论、专业工作流；已存在目标且仅需改进时使用优化路径。

输入主要是一份书籍、课程或转写文本，并要求从中提炼可调用方法时，先进入 [内容蒸馏](content.md)；人物与内容混合需求可以共用来源，但两类候选使用各自标准。

## 定位与采集

先确定技能用于什么任务。用户给定人物或主题就围绕它研究；只有需求模糊时，给少量可区分的候选及各自盲区。人物视角并不适合所有任务：领域流程优先提炼方法和证据，表达模仿只在用户需要时加入。

先查看用户提供的原始材料，再补缺口。区分：可供当前任务分析的资料、可随技能分发的资料、只能链接的资料。私有原文和书籍全文通常留在用户授权位置，技能内保留必要结论和可公开引用信息。

按材料与预算选择研究维度，不机械启动六个代理：

| 维度 | 需要回答的问题 | 候选来源 |
|---|---|---|
| 系统论述 | 核心方法、术语和论证是什么 | 本人著作、论文、官方文档 |
| 长对话 | 被追问、质疑时如何解释或修正 | 原始访谈、演讲、问答记录 |
| 表达方式 | 哪些表达特征服务于任务 | 本人文章、字幕、公开发言 |
| 外部反例 | 方法在哪里失败，有何批评 | 原始反例、独立评价、复盘 |
| 行动与结果 | 表达与实际行为是否一致 | 决策材料、产品记录、可核结果 |
| 时间与环境 | 方法何时改变，现状是否过期 | 带日期的版本、记录和原文 |

简单需求只研究有用的维度；需要充分调研时再按独立维度分工。公众人物以本人原始材料为先，非公众人物只用用户有权提供的材料。按作者身份、原文可达性、时间和证据质量评估来源，不能仅因发布平台把本人一手文章判为无效。

在 `references/research.md` 保存使用过的来源：编号、标题、作者/机构、URL或授权本地位置、日期、材料类型、支持的具体结论，以及原话/转述/推断标签。链接未打开或原文未核实的标注未核；搜索摘要不能当成已读原文。来源比例按独立材料计数，未分类项单列，不通过关键词出现次数推算。

## 框架提炼

对人物的代表性心智模型核查：

1. **复现**：是否在多个场景出现，而非一次随口表达？
2. **生成**：是否能形成对新问题可执行的分析步骤？
3. **区分**：是否体现该人物/方法的特点，而非通用口号？

这些是人物归因的判断依据，不是所有知识的通行门槛。领域共识、标准流程、公式、排障和检查表改用“来源充分性、可执行性、任务增益”三关，详见 [内容候选筛选](content.md#筛选方法与保留去向)；单处完整说明可以保留，不因不独特或出现次数少而拒绝。共识明确标为共识。

保留足以解释目标任务的模型数量，不为数量门槛编造框架。每项写：证据、触发条件、执行方法、失效条件。快速规则写成条件与行动，并给案例；争议和前后变化分开保留。

人物视角额外区分公开立场与框架推断，明确调研截止日期。默认以“基于公开材料的某人视角”呈现；用户要求角色语气时可以采用，但具体新问题仍保留不确定性与出处，不能让语气替代事实核查。

## 构建

参照 [目标技能骨架](target-template.md) 构建，不把所有研究原文塞进入口：

- `description` 描述能做什么、何时使用，避免吸收普通问答。
- 工作流有实际输入、行动、输出、完成标准；事实敏感步骤能调用宿主可用工具，工具受限时说明降级能力。
- 参考文件保存专业细节和来源，脚本只承接需要确定执行的操作。
- 将已观察到的失败转成条件分支，保留能力边界和恢复办法。

已有专业工具、接口和外部技能仅在目标环境可用时引用，并写明不可用会影响什么。主张兼容某个宿主，需要相应验证；路径可配置只能证明去除了硬编码，不能证明所有运行环境均已适配。

初稿完成后冻结首版，进入入口的共用验收。方向明确时自动继续到可审阅结果；人物身份、领域范围或分发权限存在重要歧义才先确认，不添加固定的多次中途审批。
