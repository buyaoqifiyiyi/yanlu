# 内容蒸馏：从原文到可调用的方法

适用于书籍、长文、课程、访谈、字幕、转写稿和资料集。目标是执行方法，普通摘要不走本流程；模仿作者身份则使用创建指南的人物路径。

## 取得原文并确定覆盖范围

先取得可访问的文本或能提取文字的文件，记录标题、作者/讲者、来源、版本/日期（未知如实记录）和使用目的。没有原文就请求材料或可访问位置，不能凭书名或模型记忆构造原书方法。音视频需要可用字幕或转写；OCR、语音识别和视频画面分析由宿主可用工具承担，未经执行不宣称已读取。

长资料先列章节/时间轴、主旨、核心任务、术语与作者假设，再分块阅读。为每个块保留 source_id、章节/页码/时间戳/块编号；方法涉及的表格、脚注、条件与单位一起读。选择性检索用于定位，不能代替声称覆盖范围内的完整读取；只读部分就限定范围。续跑时记录已读范围、候选和缺口，继续处理剩余内容。

以实际任务为线索提取框架、原则、步骤/公式、案例、反例和术语。材料独立且足够长时可以分工，少量文本直接串行；共享原文位置和候选 ID。用户仅允许给定材料时不补充联网知识；外部补证另标来源，不伪装成原书内容。

## 筛选方法与保留去向

对候选按类型核查：

| 三关 | 完成条件 |
|---|---|
| 来源充分性 | 原文足以支持限定范围的规则；条件、输入、步骤/公式、分支、单位和输出齐全且能回查 |
| 可执行性 | 用新的合法输入能走完明确任务，并有可检查结果；纸面演练单列，不算真实执行 |
| 任务增益 | 说明可能减少什么遗漏、统一什么口径或稳定什么交付；实际改善交给共用验收验证 |

一处完整说明可以通过，不要求重复出现、跨领域外推或作者独创；一句口号、半条公式不够，不能靠合成演练补造关键规则。人物归因所需的代表性与独特性，也不能用来淘汰工具性方法。忠实于来源和现实有效性是不同结论，保留作者假设、时效和适用边界。

按以下去向保存候选及理由：

- **eligible**：来源和执行说明充分、存在待检验的任务价值，进入能力卡构建；效果状态仍为 pending，不能称已实测。
- **reference**：有背景、案例或术语价值，放入实际可达的参考文件，不包装成能执行的能力。
- **needs_review**：关键条件缺失、冲突未解决或暂不能检验，保留具体缺口，不作为可执行能力交付。
- **rejected**：缺乏依据、错误归因或被另一项完整覆盖；记录理由，去重项关联保留的 ID。

建立“关键任务 → 原文位置 → 候选 ID → 判定 → 实际交付路径”的覆盖记录。重要方法没有对应产物就补读或列缺口；已保留的参考内容必须能从交付入口到达，不能只存在于临时研究目录。没有 eligible 候选时交付参考与缺口说明，不凑技能数。

## 能力卡与记录

为每个 eligible 方法分配稳定 ID，正文放入实际技能的 `references/capabilities/` 或同等可达位置。用以下六部分承载必要内容，不为固定篇幅删掉前置条件：

| 部分 | 必须表达的内容 |
|---|---|
| R 原文依据 | 简短引用或准确转述、source_id 与具体定位；引用遵守来源许可和当前规则 |
| I 解释 | 自己的话说明方法及其适用范围，与单纯摘要区分 |
| A1 案例 | 原文案例/例题及其出处；原文无案例则明确标注“合成演练”，结果不能冒充事实 |
| A2 触发 | 用户实际意图、典型语言信号、相邻方法的区别、何时不使用 |
| E 执行 | 必需输入、类型/单位、步骤、分支、输出与完成标准；缺输入时的处理 |
| B 边界 | 失效条件、作者假设、已知反例、知识截止与证据局限 |

计算类保留公式、运算顺序、单位、精度和容差；原文没规定的舍入规则另标为实现约定，并检验不改变含义。流程类保留角色/状态、必要依赖、失败恢复及判停。资源只添加当前执行确实需要的文件，并验证输入输出契约。

运行记录 `capabilities.json` 保存候选数组，至少有：`id`、`revision`、`title`、`type`、`source_evidence`（来源及定位）、`decision`、`reason`、`validation`（pending/passed/failed/blocked）、`destination`。eligible 项另记能力卡路径和相关方法 ID；其 destination 有且只有一个主要交付位置。reference 项记实际参考文件，待核查/淘汰项记缺口或理由位置。ID 在文案修订时保持；实质拆分/合并时登记替代关系和新 ID。

`validation` 是该能力必需验收项的汇总：全部有相应实际证据并通过才记 passed；任一必需项确定失败记 failed；存在尚未执行或仅纸面演练的必需项记 pending，前提不足无法继续则记 blocked。子检查另记状态、证据层级和范围，例如“3项公式复算通过”不能使尚未实测缺输入分支的整项能力变成 passed。此状态仍不代表相对旧版的效果提升，改善结论沿共用验收单独记录。

这是衍炉的审阅记录，不是仓颉 `verified.yaml` 编译契约；没有经过对应 schema 校验与编译，不能称为兼容 Bundle。原文、私有材料和研究底稿按权限留存，不默认随可安装技能包发布。

## 选择入口数量

默认构建一个入口，按任务路由到相关能力卡，并保存必要术语、前提及方法之间的依赖/对比。所有 eligible 卡片都能到达，参考材料也有实际链接。用户要求技能组或出现独立调用需求时，再评估拆分：

1. 用户会单独提出该任务，存在独立意图；
2. 有自己的输入、步骤、输出和验收契约；
3. 不必加载全书或多个兄弟技能即可执行；
4. 有重复使用或独立评测的实际价值。

前三项缺一则仍保留为入口内能力卡；没有单独入口不等于淘汰。满足拆分条件也不自动增加入口，以用户用途和可区分性决定。技能组的每个独立技能自包含必要资源；来源入口与独立技能说明各自处理范围，避免同一请求抢调用。不要为了压低数量把契约不同的任务硬拼在一起。

本包由 Agent 根据这些规则构建文件并验证，没有内置 single/pack 确定性编译器、注册表或自动重规划命令。

## 验收与后续更新

进入 [共用验证](validate.md)：来源溯证、能力可达/触发、实际输出分别检查。每个交付的可执行能力覆盖代表任务及关键边界/缺输入；测试计算的数值和单位，流程的分支和产物，方法选择的正例/负例/近邻混淆。缺输出或受阻用例单列，不从计划分母消失；未测试能力标 pending/blocked，重要缺口时只交付范围明确的草稿。

只将来源定位和必要解释写入卡片，不能把“来源真实”当成“任务效果已提升”。无真实对照时按入口标 unverified；对已存在技能保持相同输入、工具与独立比较要求。

新增资料时沿稳定 ID 定位受影响的卡片、依赖和测试，记录新旧来源关系，复用原输出形态；不会因为资料变多就静默把一个技能变成一组。需要拆分时先给出具体范围和差异，再按当前授权执行。
